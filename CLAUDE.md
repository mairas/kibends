# kibends

`kibends smooth` replaces each chain of track segments selected in KiCad's PCB editor (several chains per run, on any copper layers) with a short, smooth path of straight segments that keeps clearance to other copper and to the other selected chains. It talks to a running KiCad 10 through the IPC API (kicad-python, imported as `kipy`). The README is the user documentation.

The repository is public. Never write host names, addresses or other details of the author's machines into files, commits, issues or PRs.

## Commands

- `./run sync` installs dependencies, including the `plot` extra that `TestPlot` needs. Run it in every fresh worktree before testing.
- `./run test` runs the fast tier; `./run test-all` runs everything, including `slow` and real kicad-cli tests.
- `./run lint` runs `ruff check` and `ruff format --check`; `./run format` formats and applies ruff's fixes.
- `./run typecheck` runs pyright in strict mode over `src`, `tests` and `scripts`. Keep code fully annotated and never use `Any`.
- `./run check` runs lint, typecheck and `test-all`, as CI does. Run it before committing. CI has no kicad-cli, so the real-KiCad DRC tests run only locally: a change to `drc.py` needs a local `./run check` with KiCad installed.
- `./run help` lists the commands. `run` follows the halos convention: one bash function per command, documented with `#@` docstrings.

Ruff and pyright are configured in `pyproject.toml`. CI (`.github/workflows/pr.yml`) calls the halos-org shared checks workflow, which runs `.github/actions/run-tests`; kicad-cli tests skip there.

## Pipeline

`run.run_smooth` runs the stages in this order without printing. Before the DRC check and the commit, either of which may raise, it hands an `OptimizerReport` (per-chain statistics, frozen vertices, unchanged chains, each movable via's start and end, termination, abnormal bursts per problem, the optimize stage's wall time) to its `on_optimized` callback; at the end it returns a `RunReport`, which adds the DRC verdict, whether it committed and any refusal. `cli.smooth` prints the optimizer's outcome line (`format_outcome`), logs the warnings (`report_warnings`: frozen vertices and vias, an iteration cap or time limit) and logs the abnormal bursts at debug from the callback, and prints the DRC verdict from the returned report; the per-chain, per-pair and per-via figures stay in the reports and are not printed. A GUI is meant to call the same function.

1. `snapshot.read_selection` and `BoardSnapshot.read` read the selected tracks and vias and the board once per run, for the copper layers of the selection, or for every enabled copper layer when a selected via may move (`vias.may_move`: unlocked and through); `BoardSnapshot.slice` gives one `LayerSnapshot` per layer without further requests. Everything they return is free of kipy.
2. `chain.split_locked` and `chain.split_chains` (together `extract_chains`) split the selection into chains, one per connected piece of one layer, net and width, and pin each chain's ends and every point where same-net copper (pads, vias, tracks, copper shapes) on its layer touches it. A point where three or more selected tracks of one net end is a junction: the selection is split there into chains that end at it, loose unless other copper pins it. An end that reaches the copper of another selected track of its net nearest a point inside it meets it at a junction too (`chain._join_mid_track_ends`) when every track ending there may join it (`chain._may_join`): the track does not cross the other's centreline by more than the other's half width, and either it lies on the other and has its width, so that they merge, or it leaves the other's reach through its side and the selection does not already connect the two. The other is split at the nanometre point of its centreline nearest the end, and the end moves there, unless unselected copper (pads, locked tracks and the like) reaches the end where it was drawn, which would lose that copper's connection; such an end stays put. Other ends stay where they are and are pinned where copper overlaps, however close to the other's centreline. Tracks of two widths whose spans overlap stay separate chains of their own widths, pinned where their copper overlaps. Every chain the split track's parts belong to carries its id (`chain.shared_track_groups`), so `run` marks them all changed when one changes, the commit deletes it once, and the DRC gate counts them as one chain. A route through a via is one chain per layer, each pinned at the via. A via is copper and a hole only on the layers its drill spans. The copper of the selected vias that may move does not pin, so that it does not tether the chains it carries.
   `vias.movable_vias` then judges the selected vias: an unlocked through via is movable when only selected chain ends and same-net zone fills touch it, on any layer, at least two ends do, and no other copper touches those ends; `BoardSnapshot.read` finds that copper, zones and teardrops left out, since KiCad reapplies them on the next refill, from the end discs `vias.carried_copper` gives for chains extracted without pins, and records the zones of its net whose fill touches the via itself (`ViaZone`: by layer, the pieces of the current fill that touch it, and the minimum width), which a moving via stays inside. From each such fill it cuts what the next refill will leave out though an older fill covers it (`snapshot._unfillable`): the outlines of higher-priority copper zones of other nets on that layer, grown by the larger of the two zones' clearances, and of rule areas keeping out copper pour. A via connects when its centre lies `ViaZone.margin` inside the fill: half the zone's minimum width plus KiCad's default arc error (`KICAD_MAX_ERROR`, 0.005 mm; the API does not expose the board's), not its whole ring, since the fill cuts through the ring where the zone's clearance to other copper reaches it and KiCad still connects the via. A via whose centre does not start that deep inside each such fill stays fixed, with a debug line naming the zone and layer. The others stay fixed, each with a debug line naming the reason, and if any of them could have moved, the chains are extracted again with its copper pinning, so a fixed via pins as an unselected one does. Pins never change a chain's order or ends, so the via's chain ends stay valid.
3. `obstacles.build_obstacles` turns other-net copper, holes, keepouts and the board edge into obstacles inflated by the required clearance: one static field per (layer, net, width), from that layer's snapshot, with every selected track and every moving via removed. `obstacles.build_via_obstacles` gives each moving via a field over every layer it spans, the rule areas keeping out vias on those layers included (`LayerSnapshot.via_keepouts`, inflated by the via's radius as track keepouts are by half the track width), plus, for each zone it stays inside and each layer where the zone's fill touches it, the outside of that fill inflated as the board edge is, by `ViaZone.margin` (`obstacles.zone_containment`), so that the next refill connects it again. The fill, not the outline: the refill leaves out what the fill leaves out, such as a higher-priority zone of another net, a rule area keeping out pour, or the clearance around other nets' copper; its box and the via check keep it inside as they keep it off other copper.
4. `optimize.optimize_chains` minimises length + repulsion with L-BFGS-B, one problem at a time: the chains, coupled sections and moving vias of one layer, or, where moving vias tie layers together, of all those layers at once. A problem's energy is the sum of each member's energy in its static field plus the others on its layer, taken as one function of every free vertex and via centre, so the gradient where one chain repels another reaches both. An outer iteration gives every problem that has not settled one burst: resample each chain to the spacing between its fixed vertices, bound each free vertex to its bubble, a box inside the smaller of its free distance to static copper and the larger of `CROSS_SHARE` of its free distance to the other members (which move in the same burst) and a step floor, `STEP_FLOOR` of the problem's smallest inflation between two members less δ, which a vertex takes only when its edges start clear of the others, run bounded L-BFGS-B (`bursts.bounded_burst`), then move back the free ends of every edge that newly crosses static copper or another member's new shape, with halved bounds for the retry. The module docstring shows why the boxes and the edge check together keep every chain on the same side of every obstacle and of every other chain. Chains of one net see each other at touching distance and leave each other out near where they touch at fixed points (`neighbours.kept_spans`). The ends of a junction's branches are one shared variable; simplify and the statistics take the chains with those ends pinned (`optimize.pinned_at_junctions`), so that branches leave each other out at the junction. Differential pairs (`pair_layout.find_pairs`) enter as their uncoupled pieces, ordinary chains, and their coupled sections, each a centreline member (`pair_blocks`) with the bend-radius hinge, whose two offset tracks the others see and whose gradient returns through the offset (`PairBlock.offset_pullback`); `pair_layout.Layout` joins the parts back into one polyline per selected chain after simplification. The pieces' and sections' ends are fixed, so `pair_layout.lay_out` pins every loose end that meets one, as at a junction where a pair starts. A moving via (`via_moves`) is its centre's two variables; the chain ends it carries are its centre plus their offsets. A via that joins a pair's track stays fixed, and one that starts more than δ inside its clearance stays, pins the chain ends it carries and ties no layers. A section whose routing bends tighter than its inner track allows is held (`pair_blocks.Hold`); one the run leaves bent too tightly, because the copper around it (`Hold.CROWDING`) or its own parts beyond the turn (`Hold.FOLDING`, when the self check rejected moves) kept it from rounding a corner, is held too, and `run` repeats the run from the previous run's best state (`start=`), completing one outer iteration past the time limit. A burst moves back what `optimize.SelfCheck` finds on a section: an edge newly bent below the limit, or two of its parts beyond a turn brought closer than the pair's outer extent plus clearance, or closer than they started where they started closer (`optimize.close_to_itself`). Each problem keeps its best state, taken only from a burst that does not raise its energy, add violations to any member or leave a via deeper inside its clearance. A problem settles when its burst moves no shape or via by `settled_change` and moved nothing back but a section's own parts, when the lowest energy its bursts reached stalls over `stall_window` bursts, or after `MAX_ABNORMAL_BURSTS` abnormal bursts in a row; the run converges when every problem has settled, and otherwise stops at `OptimizerSettings.max_iterations` or, with a `time_limit` (`--time-limit`), after the first burst that ends past it, counted from the start of the whole stage, keeping each problem's best state either way. The defaults were measured against looser ones in https://github.com/mairas/kibends/issues/27 and https://github.com/mairas/kibends/issues/28: `lbfgs_ftol` 1e-9 costs more than 5 µm of summed length over the scenarios. `burst_maxiter` is 100 because smoothing is a visual task that does not need the exact optimum: 300 take twice the scenarios' CPU time to shorten the 34 scenarios' summed length by 12.6 µm.
5. `simplify.simplify_chains` merges each optimised polyline back into few straight segments within `--chord-tolerance`, re-checking each merged edge against the static field, the other chains and the moved vias at their final positions. A coupled pair section is simplified as its centreline, first, against the field the optimizer gave it, and its two tracks are offset from the simplified centreline as the optimizer offsets them.
6. A chain whose result equals its selected tracks, and that shares no split track with a changed chain, is unchanged: it is left out of the DRC check and the commit, and if every chain is unchanged nothing is committed.
7. `drc.check` runs `kicad-cli pcb drc` once on the board text without its teardrop zones, which KiCad reapplies on the next refill, and once with every changed chain replaced and every moved via's block rewritten at its new position under a new uuid, and the run is refused if violations rise. A moved via counts like a chain, so violations it already had are not new. `--no-drc` skips it.
8. `commit.commit_chains` re-reads the changed chains' tracks and the moved vias in one request and refuses if any changed, then deletes the old tracks and vias and creates the new tracks and a moved copy of each via in one KiCad commit.

## Invariants

- One run is one undo step in KiCad. kibends never refills zones; the user refills them or lets KiCad's DRC do it. A moved via stays inside the current fill of every zone of its net that touched it, on each layer where it did, so that the refill reconnects it.
- Locked tracks, other nets' copper, unselected or fixed vias and pads are never modified.
- Pinned points stay where they are, except chain ends at a moving via, which keep their offset from its centre. The loose ends of a junction's branches move together and stay one point. KiCad connects two tracks when their copper overlaps, not only when an end lies on the other's centreline, so pinning uses both tracks' half widths.
- Any failure before the push, in any chain, drops the whole commit, and an interrupt ends the run with "nothing committed". A connection loss or an interrupt during the push is reported as "may have landed", never as success.
- Arc tracks are refused; output is always straight tracks.

## Units and coordinates

Segment endpoints and widths from KiCad are integer nanometres, so endpoint matching is exact. Everything after the snapshot is millimetre floats and shapely geometry. All coordinates are in KiCad's board frame, with y pointing down. Printed positions are relative to the board's grid origin instead: `snapshot.read_user_frame` reads it once per run, `run_smooth` passes the `coords.UserFrame` to whatever writes a message and puts it in its report, and every printed point goes through `UserFrame.point`. Reports keep their positions in the board frame and carry the frame; their descriptions, such as a chain's, are text already formatted in it. kicad-cli's DRC report positions are in the board frame too.

## KiCad API limits

- kicad-python 0.8.0 cannot read board design rules: no minimum clearance, no custom rules, no edge or hole clearance. The optimizer uses netclass clearances plus `--edge-clearance` and `--hole-clearance`, and the kicad-cli DRC gate catches everything else. Recheck newer kicad-python releases for a rules getter.
- An intermittent "KiCad is busy" error (`AS_BUSY`) means the user has a tool or dialog open in the PCB editor. It is not a code regression. Every IPC failure ends the run with one log line through `cli._exit_on_failure`, except a copper-text render KiCad refuses for another reason, which only warns and leaves the text to the DRC check.
- The DRC gate edits the board as text and depends on KiCad 10's file format (`drc.inject`, `drc.remove_segments`, `drc.move_vias`, `drc.remove_teardrops`).

## Tests

Tests never need a running KiCad. `tests/conftest.py` provides kipy object builders and fake boards (`FakeBoard`, `CommitBoard`). `tests/scenarios.py` holds optimizer scenarios, which `scripts/plot_scenarios.py` also renders for tuning. `tests/test_optimize.py` runs single chains through `optimize.optimize`; `tests/test_optimize_chains.py`, `_pairs.py` and `_vias.py` run problems of several chains, junctions, coupled sections and moving vias through `optimize.optimize_chains`, and check the problem's energy and gradient against references built member by member. `conftest.BurstClock` is a clock that reads one per burst of a problem. Tests marked `kicad_cli` run the real kicad-cli (`conftest.KICAD_CLI`) on the boards in `tests/fixtures` and skip when it is not installed; `test_cli.TestKiCadCliZone` runs whole runs on the zone fixture through a fake board that mirrors it, with its fill refilled by kicad-cli.

### Test speed

A slow suite slows every edit-test cycle for the person running it. Treat test run time as a requirement, not a detail.

- `./run test` (the fast tier) finishes in under 10 s wall-clock.
- No test in the fast tier takes more than 1 s on its own, setup included. Measure with `.venv/bin/python -m pytest -n0 -m "not slow" --durations=10`; the parallel run hides slow tests.
- Make a slow test faster before marking it `slow`: coarser optimizer settings, a smaller scenario, a fake instead of the real kicad-cli. Mark it `slow` only when it needs the real thing, such as the kicad-cli tests.
- Every change that adds or modifies tests checks the durations above and reports the fast-tier time.
