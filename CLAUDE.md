# kibends

`kibends smooth` replaces each chain of track segments selected in KiCad's PCB editor (several chains per run, on any copper layers) with a short, smooth path of straight segments that keeps clearance to other copper and to the other selected chains. It talks to a running KiCad 10 through the IPC API (kicad-python, imported as `kipy`). The README is the user documentation.

The repository is public. Never write host names, addresses or other details of the author's machines into files, commits, issues or PRs.

## Commands

- `./run sync` installs dependencies, including the `plot` extra that `TestPlot` needs. Run it in every fresh worktree before testing.
- `./run test` runs the fast tier; `./run test-all` runs everything, including `slow` tests.
- `./run lint` runs `ruff check` and `ruff format --check`; `./run format` formats and applies ruff's fixes.
- `./run typecheck` runs pyright in strict mode over `src`, `tests` and `scripts`. Keep code fully annotated and never use `Any`.
- `./run check` runs lint, typecheck and `test-all`, as CI does. Run it before committing.
- `./run help` lists the commands. `run` follows the halos convention: one bash function per command, documented with `#@` docstrings.

Ruff and pyright are configured in `pyproject.toml`. CI (`.github/workflows/pr.yml`) calls the halos-org shared checks workflow, which runs `.github/actions/run-tests`.

## Pipeline

`run.run_smooth` runs the stages in this order without printing. Before the commit, which may raise, it hands an `OptimizerReport` (per-chain statistics, frozen vertices, unchanged chains, each movable via's start and end, termination, abnormal bursts per problem, the optimize stage's wall time) to its `on_optimized` callback; at the end it returns a `RunReport`, which adds whether it committed and any refusal. `cli.smooth` prints the optimizer's outcome line (`format_outcome`), logs the warnings (`report_warnings`: frozen vertices, an iteration cap or time limit) and logs the frozen vias and abnormal bursts at debug from the callback, and raises the returned report's refusal; the per-chain, per-pair and per-via figures stay in the reports and are not printed. A GUI is meant to call the same function.

1. `snapshot.read_selection` and `BoardSnapshot.read` read the selected tracks and vias and the board once per run, for the copper layers of the selection, or for every enabled copper layer when a selected via may move (`vias.may_move`: unlocked and through); `BoardSnapshot.slice` gives one `LayerSnapshot` per layer without further requests. Everything they return is free of kipy.
2. `chain.split_locked` and `chain.split_chains` (together `extract_chains`) split the selection into chains, one per connected piece of one layer, net and width, and pin each chain's ends and every point where same-net copper (pads, vias, tracks, copper shapes) on its layer touches it. A point where three or more selected tracks of one net end is a junction: the selection is split there into chains that end at it, loose unless other copper pins it. First, a track redrawn along another of its width merges into it (`chain._merge_duplicates`), one at a time, longest first, judged again on the result each time, until none merges: both its ends lie inside the other's copper on one side of its centreline, at least a width apart along it, each at one of the other's ends or cuts or beside a point inside it, where it lands (`chain._runs_along`). The host is the nearest drawn track of its width that has not merged and none of whose ends or cuts has moved, so that its pieces still lie on its line; a host is no shorter than the tracks along it, so it has merged, if it can, before them. A merge is skipped where it would close a loop (`chain._closes_no_loop`) or where copper of the net, unselected or selected, reaches the track's copper but not the host's, which would lose its connection (`chain._keeps_copper`). The host is cut where the track's ends land, the track becomes copies of the host's pieces between them, which carry its id and coincide with the host's, and every track ending at a moved end moves with it. Then an end that reaches the copper of another selected track of its net nearest a point inside it meets it at a junction too (`chain._join_mid_track_ends`) when every track ending there may join it (`chain._may_join`): the track does not cross the other's centreline by more than the other's half width, and either it lies on the other and has its width, so that they merge, or it leaves the other's reach through its side and the selection does not already connect the two. The other is split at the nanometre point of its centreline nearest the end, and the end moves there, unless unselected copper (pads, locked tracks and the like) reaches the end where it was drawn, which would lose that copper's connection; such an end stays put. Other ends stay where they are and are pinned where copper overlaps, however close to the other's centreline. Tracks of two widths whose spans overlap stay separate chains of their own widths, pinned where their copper overlaps. Every chain the split track's parts belong to carries its id (`chain.shared_track_groups`), so `run` marks them all changed when one changes, and the commit deletes it once. A route through a via is one chain per layer, each pinned at the via. A via is copper and a hole only on the layers its drill spans. The copper of the selected vias that may move does not pin, so that it does not tether the chains it carries.
   `vias.movable_vias` then judges the selected vias: an unlocked through via is movable when only selected chain ends and same-net zones touch it, on any layer, at least two ends do, and no other copper touches those ends, or when no end and no other copper touches it but the snapshot gives it a zone of its net (`via_zones` not empty), a stitching via, which carries no chain. With `--fixed-vias` (`SmoothOptions.fixed_vias`), `run._carrying` first takes every candidate that carries no chain end out of the candidates, before the board is read, each with a debug line naming the flag, so it pins as an unselected via, costs no via field, and a selection whose only candidates are such vias reads no more layers than one without them; vias that carry chain ends move as without the flag; `BoardSnapshot.read` finds that copper, zones and teardrops left out, since KiCad reapplies them on the next refill, from the end discs `vias.carried_copper` gives for chains extracted without pins, and records the zones of its net that may connect to the via (`ViaZone`: by layer, for the layers where its region reaches the via's ring, the zone's region, its minimum width and its clearance), which a moving via stays inside. kibends never reads a zone's fill: it holds where other copper stood at the last refill and turns stale once the run moves copper. A copper zone of the via's net may connect to it when, on a layer the via spans, the zone's region reaches the via's ring (lies within its radius of its centre); a via whose ring no such region reaches is not zoned, and moves as a via in free space. The next refill connects a via whose centre lies `ViaZone.margin` inside the region: half the zone's minimum width plus KiCad's default arc error (`KICAD_MAX_ERROR`, 0.005 mm; the API does not expose the board's), not its whole ring, since the fill cuts through the ring where the zone's clearance to other copper reaches it and KiCad still connects the via. The zones of its net count together on each layer (`snapshot.zone_unions`): the refill connects the via through any of them, so it is judged and held against `ZoneUnion.centres`, the union of each zone's region shrunk by its own margin and of the union of their regions shrunk by the largest of their margins. A via deep enough inside one zone by that zone's margin is connected whatever the others do, and one on the seam of two zones meeting edge to edge is connected by both fills, which reach the seam, but only as deep as the widest minimum width among them keeps. The vias of one plane share its region objects, and `snapshot._centres` and `_shrunk` cache the shrunk shapes by region and margin, so a run shrinks each region once however many vias it reaches. Two zones of one net that overlap, or meet edge to edge, then hold a via deep inside one of them, or on their seam, although the other's outline crosses its ring. A zoned via whose centre does not start inside `centres` on each such layer may be connected only now, so it stays fixed, with a debug line naming the zones and layers. The region is built from outlines and priorities alone, once per zone and layer per run (`snapshot._zone_region`), and only for a zone whose outline reaches a selected via's ring: the zone's outline with its own cut-outs, less the outlines of copper zones of other nets on that layer whose priority is higher or equal (KiCad breaks a tie by uuid), grown by the larger of the two zones' clearances, and of rule areas keeping out copper pour. A via that a zone's region reaches but the current fill misses still counts as connected. One that starts closer than the zone's clearance and margin to other-net copper is the optimizer's to hold, as any via starting inside its clearance. Thermal reliefs, island removal, hatched fills and minimum-width necks are not modelled. The others stay fixed, each with a debug line naming the reason, and if any of them could have moved, the chains are extracted again with its copper pinning, so a fixed via pins as an unselected one does. Pins never change a chain's order or ends, so the via's chain ends stay valid.
3. `obstacles.build_obstacles` turns other-net copper, holes, keepouts and the board edge into obstacles inflated by the required clearance: one static field per (layer, net, width), from that layer's snapshot, with every selected track and every moving via removed. `obstacles.build_via_obstacles` gives each moving via a field over every layer it spans, the rule areas keeping out vias on those layers included (`LayerSnapshot.via_keepouts`, inflated by the via's radius as track keepouts are by half the track width), and `ViaInput.stops` adds, for each layer where the regions of the zones it stays inside reach it, the outside of `ZoneUnion.centres`, held as the board edge is (`obstacles.containment`), a limit that does not repel, as are the vias of its net that stand still (`obstacles.own_net_vias`), which `build_via_obstacles` leaves out of its field and `ViaInput.own_net` carries, their holes at hole-to-hole and nothing else, as two moving vias of one net keep. On those layers the via also keeps the zone's clearance plus the margin from other-net copper where that exceeds the netclass rule (`obstacles._zone_inflation`, through `_Keeper.zones`), since the refill keeps that clearance from it: static copper in this field, and the chains and vias moving in the same run in its member terms (`via_moves.MovingVias.ring` and `apart`, and `moving_via_obstacles` for the chains that see it alike); two vias keep the larger of their zone distances both ways. Whether a via starts inside its clearance, and so stays, is judged by its own zones alone (`MovingVias.field`): when it starts inside another via's zone distance, that via starts as deep inside its own and stays. A via that stays is seen without its zones (`MovingVias.standing`), as an unselected via: standing still, it connects as it does now. So the via keeps clear of other copper where it is now, not where the fill last saw it.
4. `optimize.optimize_chains` minimises length + repulsion with L-BFGS-B, one problem at a time: the chains, coupled sections and moving vias of one layer, or, where moving vias tie layers together, of all those layers at once. A problem's energy is the sum of each member's energy in its static field plus the others on its layer, taken as one function of every free vertex and via centre, so the gradient where one chain repels another reaches both. One evaluation searches what every member sees of the others with one tree per layer, and what every moving via sees with one more (`seen.Seen`, `seen.ViaSight`), each pair of a point and an edge standing for the pieces of it that the point's member sees, so the answers are those a field of each member's own pieces gives. An outer iteration gives every problem that has not settled one burst: resample each chain to the spacing between its fixed vertices, bound each free vertex to its bubble, a box inside the smaller of its free distance to static copper and the larger of `CROSS_SHARE` of its free distance to the other members (which move in the same burst) and a step floor, `STEP_FLOOR` of the problem's smallest inflation between two members less δ, which a vertex takes only when its edges start clear of the others, run bounded L-BFGS-B (`bursts.bounded_burst`), then move back the free ends of every edge that newly crosses static copper or another member's new shape, with halved bounds for the retry. The module docstring shows why the boxes and the edge check together keep every chain on the same side of every obstacle and of every other chain. Chains of one net see each other at touching distance and leave each other out near where they touch at fixed points (`neighbours.kept_spans`). The ends of a junction's branches are one shared variable; simplify and the statistics take the chains with those ends pinned (`optimize.pinned_at_junctions`), so that branches leave each other out at the junction. Differential pairs (`pair_layout.find_pairs`) enter as their uncoupled pieces, ordinary chains, and their coupled sections, each a centreline member (`pair_blocks`) with the bend-radius hinge, whose two offset tracks the others see and whose gradient returns through the offset (`PairBlock.offset_pullback`); `pair_layout.Layout` joins the parts back into one polyline per selected chain after simplification. `pairs.find_pair` splits a coupled stretch at each vertex where same-net copper pins either track and both tracks run straight for `STRAIGHT_PITCHES` pitches to either side (`pairs._Splits`), and square across from it on the other track, where the gap is the stretch's, so sections end at pins with the pair's gap and keep room to round their corners within the bend-radius limit; stations are ordered by vertex index, and one that does not advance on both tracks is dropped. A pin that splits nothing, near a corner, on a curve or out of order, holds the section it lies in (`Hold.COPPER`), and a section left with no vertex to move, every stretch between its ends and direction pins a spacing or shorter, or a track a spacing or shorter, is held as routed (`Hold.SHORT`), neither with a warning. The pieces' and sections' ends are fixed, so `pair_layout.lay_out` pins every loose end that meets one, as at a junction where a pair starts. A moving via (`via_moves`) is its centre's two variables; the chain ends it carries are its centre plus their offsets. A stitching via carries none and has no length term, so only repulsion within `--range` moves it: from its static field and from the chains and vias of other nets near it, and from a chain of its net, kept at touching distance. Two vias of one net, moving or standing still, keep only their limit and do not repel each other, and a zone's region only limits a via (both in `ViaInput.stops`): in `_Problem.via_energy` each via has a full term for the nearest of its static field and what repels it, and a clearance-hinge term (`energy.hinge_integrand`) for the nearest of its zones' outside and the vias of its net; bubbles, the via check and the frozen judgement use both (`ViaInput.limits`). `_Problem.via_statics` finds every moving via's distances to its static field and to its stops in one loop, one lookup per via and part (`_ViaPart` keeps each part's field, sight and integrand together), and each of the two integrands is applied, and its gradient scattered, to every via at once. `build_via_obstacles` leaves the zones' regions out, so the board edge and other static copper repel as before. `ViaInput.clearance` gives each via's netclass clearance, since a stitching via's net may have no chain. With many moving vias, their per-via static lookups dominate their own terms: on a grid of 194 stitching vias in one zone, an evaluation of those terms took 13 ms, most of it in querying each via's own field and stops, one shapely or k-d tree query per part (https://github.com/mairas/kibends/issues/74). A via that joins a pair's track stays fixed, and one that starts more than δ inside its clearance stays, pins the chain ends it carries and ties no layers. A section whose routing bends tighter than its inner track allows is held (`pair_blocks.Hold`); one the run leaves bent too tightly, because the copper around it (`Hold.CROWDING`) or its own parts beyond the turn (`Hold.FOLDING`, when the self check rejected moves) kept it from rounding a corner, is held too, and `run` repeats the run from the previous run's best state (`start=`), completing one outer iteration past the time limit. A burst moves back what `optimize.SelfCheck` finds on a section: an edge newly bent below the limit, or two of its parts beyond a turn brought closer than the pair's outer extent plus clearance, or closer than they started where they started closer (`optimize.close_to_itself`). Each problem keeps its best state, taken only from a burst that does not raise its energy, add violations to any member or leave a via deeper inside its clearance. A problem settles when its burst moves no shape or via by `settled_change` and moved nothing back but a section's own parts, when the lowest energy its bursts reached stalls over `stall_window` bursts, or after `MAX_ABNORMAL_BURSTS` abnormal bursts in a row; the run converges when every problem has settled, and otherwise stops at `OptimizerSettings.max_iterations` or, with a `time_limit` (`--time-limit`), after the first burst that ends past it, counted from the start of the whole stage, keeping each problem's best state either way. The stop rules were measured in https://github.com/mairas/kibends/issues/27 and https://github.com/mairas/kibends/issues/28, the burst length and `lbfgs_ftol` in https://github.com/mairas/kibends/issues/70. Smoothing is a visual task that does not need the exact optimum, and almost every burst runs to `burst_maxiter`, so the cap sets the cost: at 50 with `lbfgs_ftol` 1e-9 the 38 scenarios take 44% fewer energy evaluations than at 100 with 1e-15 and end 30 µm longer in sum, and a synthetic problem of 120 chains and 30 moving vias reaches its final length in half the evaluations. At 25 a coupled section settles visibly short of its shape.
5. `simplify.simplify_chains` merges each optimised polyline back into few straight segments within `--chord-tolerance`, re-checking each merged edge against the static field, the other chains and the moved vias at their final positions. A coupled pair section is simplified as its centreline, first, against the field the optimizer gave it, and its two tracks are offset from the simplified centreline as the optimizer offsets them.
6. A chain whose result equals its selected tracks, and that shares no split track with a changed chain, is unchanged: it is left out of the commit, and if every chain is unchanged and no via moved, nothing is committed.
7. `commit.commit_chains` re-reads the changed chains' tracks and the moved vias in one request and refuses if any changed, then deletes the old tracks and vias and creates the new tracks and a moved copy of each via in one KiCad commit.

## Invariants

- One run is one undo step in KiCad. kibends never refills zones and never runs KiCad's DRC; the user refills the zones or lets KiCad's DRC do it, and runs the DRC for everything the optimizer does not model (custom rules, board minimums, thermal reliefs, island removal, hatched fills, minimum-width necks). A moved via stays where the zones of its net whose region reached its ring connect it taken together (`ZoneUnion.centres`), on each layer where one did, and keeps the zone's clearance and margin from other-net copper there, so that the refill reconnects it.
- Locked tracks, other nets' copper, unselected or fixed vias and pads are never modified.
- Pinned points stay where they are, except chain ends at a moving via, which keep their offset from its centre. The loose ends of a junction's branches move together and stay one point. KiCad connects two tracks when their copper overlaps, not only when an end lies on the other's centreline, so pinning uses both tracks' half widths.
- Any failure before the push, in any chain, drops the whole commit, and an interrupt ends the run with "nothing committed". A connection loss or an interrupt during the push is reported as "may have landed", never as success.
- Arc tracks are refused; output is always straight tracks.

## Units and coordinates

Segment endpoints and widths from KiCad are integer nanometres, so endpoint matching is exact. Everything after the snapshot is millimetre floats and shapely geometry. All coordinates are in KiCad's board frame, with y pointing down. Printed positions are relative to the board's grid origin instead: `snapshot.read_user_frame` reads it once per run, `run_smooth` passes the `coords.UserFrame` to whatever writes a message and puts it in its report, and every printed point goes through `UserFrame.point`. Reports keep their positions in the board frame and carry the frame; their descriptions, such as a chain's, are text already formatted in it.

## KiCad API limits

- kicad-python 0.8.0 cannot read board design rules: no minimum clearance, no custom rules, no edge or hole clearance. The optimizer uses netclass clearances plus `--edge-clearance` and `--hole-clearance`; the user's own KiCad DRC run checks everything else. Recheck newer kicad-python releases for a rules getter.
- An intermittent "KiCad is busy" error (`AS_BUSY`) means the user has a tool or dialog open in the PCB editor. It is not a code regression. Every IPC failure ends the run with one log line through `cli._exit_on_failure`, except a copper-text render KiCad refuses for another reason, which only warns and leaves the text to KiCad's DRC.

## Tests

Tests never need a running KiCad. `tests/conftest.py` provides kipy object builders and fake boards (`FakeBoard`, `CommitBoard`). `tests/scenarios.py` holds optimizer scenarios, which `scripts/plot_scenarios.py` also renders for tuning. `tests/test_optimize.py` runs single chains through `optimize.optimize`; `tests/test_optimize_chains.py`, `_pairs.py` and `_vias.py` run problems of several chains, junctions, coupled sections and moving vias through `optimize.optimize_chains`, and check the problem's energy and gradient against references built member by member. `tests/test_shared_search.py` checks the shared search against fields built for each member and via alone, on every scenario with moving members and a grid of routes through vias (`scenarios.via_grid`). `conftest.BurstClock` is a clock that reads one per burst of a problem.

### Test speed

A slow suite slows every edit-test cycle for the person running it. Treat test run time as a requirement, not a detail.

- `./run test` (the fast tier) finishes in under 10 s wall-clock.
- No test in the fast tier takes more than 1 s on its own, setup included. Measure with `.venv/bin/python -m pytest -n0 -m "not slow" --durations=10`; the parallel run hides slow tests.
- Make a slow test faster before marking it `slow`: coarser optimizer settings, a smaller scenario, a fake instead of the real thing. Mark it `slow` only when it needs the real thing.
- Every change that adds or modifies tests checks the durations above and reports the fast-tier time.
